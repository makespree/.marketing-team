# Workflows

Enter at the requested stage; don't restart research on every revision.
Every workflow uses the same project vault and brief.

## Product discovery and launch
Study the actual product → identify audience and alternatives → draft positioning
with proof → select the launch idea → design the reveal/demo and channel sequence →
create the authorized samples → review → owner decision → authorized release →
measure the agreed outcome.
Use agency-product-marketing, agency-customer-research and agency-launch.
A proposed feature must never become a demonstrated capability.

## Original campaign or content
Research the wider audience world → articulate an insight → develop distinct creative
territories → choose a route within the user's authorization → write copy/storyboard →
art direction → produce one representative piece → inspect/revise → scale the set.
Use agency-content-strategy, agency-copywriting and agency-visual-production.
Separate reusable style rules from the actual art needed to tell this new story.
A reused prop is useful only when it serves the new idea.

## Reference restage
Inspect the full reference → identify why it works → map preserve/borrow/explore →
propose the adaptation if not already specified → asset plan → original production →
compare the intended visual and temporal qualities → revise → review.
Use agency-reference-restage. Same music is a request to preserve pacing; record
the actual permitted use of the audio separately. Image/carousel references need
composition and swipe logic, not an unnecessary video pipeline.

## Revision
Read the exact version and feedback → state the missed principle → repair the
responsible component → recheck the entire affected set → retain prior versions →
submit a new revision. Don't append patches that preserve the underlying failure.
Changing caption/media invalidates that exact version's approval; it does not
erase past distribution receipts or alter already scheduled external content.

## Delivery and learning
Prepare final ordered files, caption, accessibility text, source credits and hashes →
review exact version → use authorized destination adapter → read back stored result →
save receipt → retrieve real performance for the agreed window → decide the next test.
Never run a whole-library backup as an incidental step. Reconcile uncertain uploads
before retrying. Platform success, studio review, queued scheduling and verified live
publication are distinct events even if a project's UI labels them differently.
Use agency-content-review and agency-analytics.

## Private review website
Use [Firebase review](firebase-review.md) to connect the agency vault to the
optional existing studio runtime: selected exports → verified private cloud card →
human review → feedback → versioned revision. Reuse an existing project deployment.
A new project gets its own configuration and invited reviewers. Deployment is a
one-time authorized setup, not a content-generation side effect.

## When blocked
Unavailable generation or renderer: finish the brief, asset specification and editable
source when possible; identify the missing capability. No automatic paid substitution.
Missing product truth: omit the claim or mark the direction provisional.
Missing reference: request the reference; don't pretend it was inspected.
No results access: produce a measurement plan, not imaginary performance.
