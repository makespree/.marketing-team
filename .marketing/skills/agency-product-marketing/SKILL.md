# Product marketing context

Read the active project's .marketing/vault/product/context.md, brand/guidelines.md
and decisions/log.md. Inspect the actual product, README and relevant flows.
Draft from available evidence; ask only for missing decisions that materially affect
the assignment. Do not force an interview when the repo already answers it.

Capture the useful parts of:
- Product: what it does now, category, business model, prices if verified.
- Audience: best-fit users, buying roles when relevant, trigger and job to be done.
- Alternatives: direct competitor, another approach, manual work or doing nothing.
- Differentiation: capability → customer value → supporting proof.
- Switching: push, pull, habit and anxiety.
- Objections and people this product does not serve well.
- Voice of customer: exact sourced language, context and date.
- Proof: verified results, approved testimonials and usable logos; unknown if absent.
- Goal: intended action, current baseline and what is measured.

Distinguish implementation, live availability, roadmap and positioning hypothesis.
Do not fill unknowns with invented personas, metrics, customers or prices.
Use the April Dunford lens in agency-director when positioning is the core task.
For a new product, write a useful draft, identify the few pivotal uncertainties,
and let the owner correct it. Status remains draft until accepted.

Save to .marketing/vault/product/context.md. Version substantive changes with
date, reason and source evidence; preserve earlier decision history. Other skills
read this file. If an older context exists elsewhere, reference/import only the
approved current material; don't move or delete source files automatically.
